# MVP-план: путь до прода

Состояние на 1 октября 2026. Обновлять по мере мержа PR.

## Что значит «можно в прод»

Идём в прод, когда выполнены **все** пункты. Каждый проверяется, а не «кажется готовым».

**Надёжность**
- [ ] CI зелёный на `main`: сборка клиента и сервера, тесты, `npm run rtp`.
- [ ] `main` защищён: мерж только через PR и при зелёном CI.
- [ ] Тесты покрывают выплаты, параллельные спины, ежедневный бонус, регистрацию и вход.

**Данные** (одна база для прода и разработки — решение владельца)
- [ ] Кластер на платном уровне с бэкапами; восстановление из бэкапа один раз проверено.
- [ ] Network Access: IP сервера и IP разработчика, без `0.0.0.0/0`.
- [ ] Тесты и скрипты трогают только пользователей с префиксом `probe_` и удаляют их за собой.
- [ ] Нет скриптов, которые массово удаляют или меняют данные без явного флага подтверждения.

**Эксплуатация**
- [ ] Сайт и API на одном домене с HTTPS, `NODE_ENV=production`.
- [ ] Ошибки клиента и сервера уходят в трекер ошибок, есть алерт на падение `/api/health`.
- [ ] Деплой одной командой или автоматически из `main`, есть способ откатиться.

**Продукт и игроки**
- [ ] Новый игрок проходит путь «главная → регистрация → спины → ноль → бонус» без ошибок на телефоне и десктопе.
- [ ] Есть удаление аккаунта и напоминание о длительности сессии.
- [ ] Основной язык сайта — украинский.

**Соответствие и безопасность**
- [ ] Пройден `compliance-check` по конституции: нет пути от коинов к ценности.
- [ ] Пройдено security-ревью всего сервера.
- [ ] Запуск полностью некоммерческий: нет платежей, рекламы, донатов и партнёрок (юрист не нужен, пока это так).
- [ ] `docs/assets.md` заполнен для каждого стороннего ассета, лицензии из разрешённого списка.
- [ ] Название сайта и игр проверено по реестрам торговых марок.
- [ ] Лицензии production-зависимостей npm разрешительные.

**Аналитика, поддержка, отзывы**
- [ ] События игроков пишутся в базу, отчёт показывает D1, D7, спинов на сессию, долю дошедших до нуля, отзывы за период.
- [ ] Страница поддержки с формой обращения, ссылка на неё в футере и на игровом экране.
- [ ] Форма отзыва в игре: отзыв сохраняется в базе и приходит письмом на почту поддержки.
- [ ] Почта поддержки нигде не видна: ни на сайте, ни в ответах API, ни в репозитории.
- [ ] Тестовое обращение и тестовый отзыв дошли до почты с прода.
- [ ] Политика конфиденциальности описывает события аналитики, отзывы и переписку с поддержкой.

**Запуск**
- [ ] Боевой домен, sitemap и canonical на нём, сайт добавлен в Google Search Console.

## Решения до старта

Нужны от владельца продукта. Рядом — рекомендация.

| Вопрос | Рекомендация |
|---|---|
| Хостинг | один Node-сервис (Render, Railway или Fly) в регионе Франкфурт, рядом с Atlas |
| База | **решено:** одна для прода и разработки; к запуску — платный уровень с бэкапами (Flex или M10) |
| Языки | украинский основной, русский — вторая версия позже |
| Ежедневный бонус | небольшой бонус каждый день всем, плюс текущий «спасательный» при нуле |
| Трекер ошибок | Sentry, бесплатного плана хватит |
| Аналитика | **обязательна к запуску.** Самописные события в MongoDB: без сторонних трекеров, cookie-баннера и передачи данных третьим лицам |
| Поддержка | **обязательна к запуску, почта закрытая.** Игрок пишет через форму, сервер пересылает на почту из `server/.env`. Ответ из Gmail покажет адрес этому игроку; если это нежелательно — отдельный ящик для ответов или ответы внутри сайта (вне MVP) |
| Отзывы | **обязательны к запуску.** Форма в игре → база + письмо на почту поддержки через Gmail SMTP (пароль приложения, нужна двухфакторная аутентификация в Google) |
| Восстановление пароля | почты при регистрации нет, поэтому поддержка не может безопасно вернуть доступ. Рекомендация: код восстановления, который показывается один раз при регистрации |
| Монетизация в MVP | никакой. Ни платежей, ни рекламы до юриста |

## Этапы

Один этап — один или несколько PR. Внутри этапа задачи можно делать параллельно, но каждую в своём worktree и своей ветке.

| Этап | Цель | Задачи |
|---|---|---|
| 0. Закрыть хвосты | чистый `main` | 0.1, 0.2 |
| 1. Страховка | CI, тесты, безопасная работа с общей базой | 1.1, 1.2, 1.3 |
| 2. Инфраструктура | сайт живёт на стейджинге | 2.1, 2.2, 2.3 |
| 3. Продукт | MVP, который хочется открыть завтра | 3.1, 3.2, 3.3, 3.4 |
| 3б. Обратная связь | видим, что делают игроки, и слышим их | 3.5, 3.6, 3.7, 3.8 |
| 4. Запуск | все пункты «можно в прод» отмечены | 4.1, 4.2, 4.3 |

Сроки, статусы и правило «успеваем ли» — в `docs/roadmap.md`. Целевой запуск — 6 ноября 2026.

### 1.1 CI в GitHub Actions

```text
Добавь CI в GitHub Actions для PR и пушей в main.

Шаги: Node из .nvmrc, npm ci в корне, client и server; сборка клиента и сервера;
npm run rtp в server; тесты сервера; ng test в клиенте в headless-режиме.

База одна для прода и разработки, поэтому в CI запускаются только тесты без базы
(выплаты, RTP, валидация, чистые функции). Тесты с базой запускаются вручную через
npm run test:db и в CI не попадают. Строку подключения к базе в секреты GitHub не клади.
Локальный mongod и mongodb-memory-server не используй — см. конституцию.

Готово, когда: workflow зелёный на PR, в README есть раздел "CI": что проверяется
автоматически, а что (тесты с базой) — вручную перед мержем.
После мержа напомни мне включить защиту ветки main с обязательным CI.
```

### 1.2 Тесты сервера

```text
Покрой сервер тестами на node:test (без новых фреймворков). Два скрипта в server:
npm test — без базы, для CI; npm run test:db — с базой, вручную.

Нужны:
- payout Neon Fruits: все тройки, все пары, проигрыш; таблица ожиданий в тесте.
- ежедневный бонус: выдаётся при балансе < 10, не выдаётся второй раз за киевские сутки,
  не выдаётся при балансе >= 10, смена суток по Europe/Kyiv (передавай now явно).
- регистрация и вход через HTTP: занятое имя, неверный пароль, блокировка после 5 попыток.
- перенеси test/settle-spin.ts под npm run test:db.

База одна для прода и разработки: тесты с базой создают только пользователей probe_<random>,
удаляют их (и их сессии, журнал) в finally, никаких удалений без фильтра по userId.
Чистые функции (payout, canClaimDaily, kyivDay, валидация) тестируй без базы.
Готово, когда: npm test зелёный в CI, npm run test:db зелёный локально, покрыты все пункты выше.
```

### 2.1 Один сервис для сайта и API

```text
Сделай так, чтобы прод запускался одним Node-процессом на одном домене:

регистрация и спин проходят. Опиши в README, как это запустить.

3. Каждый отзыв отправляется письмом на SUPPORT_EMAIL через модуль отправки из задачи 3.6.
   Ошибка отправки письма не ломает ответ игроку: отзыв уже в базе. SUPPORT_EMAIL
   не попадает в ответы API, HTML, клиентский код и логи.
4. Тема письма: "[Відгук] <оценка>★ <категория> — <логин или гість>". В письме нет
   паролей, токенов и cookie.
5. Скрипт server/scripts/feedback.ts выводит новые отзывы и помечает просмотренные.
6. Опиши отзывы в политике конфиденциальности.

Тесты: валидация, лимит, отзыв сохраняется при упавшем SMTP.
```

### 3.8 Восстановление доступа

```text
У игроков нет почты в аккаунте, поэтому поддержка не может безопасно вернуть доступ.
Добавь код восстановления:

1. При регистрации сервер генерирует код (например 4 группы по 5 символов), показывает
   его один раз с просьбой сохранить, в базе хранится только хеш (scrypt, как пароль).
2. Страница "Забули пароль": логин + код + новый пароль. При успехе — новый код
   показывается один раз, старый сгорает, все сессии игрока завершаются.
3. Лимит попыток как у входа. Ответы не раскрывают, существует ли логин.
4. Существующим игрокам — предложение создать код при следующем входе.
5. В FAQ поддержки: без кода доступ восстановить нельзя.

Тесты: успешное восстановление, неверный код, повторное использование кода, лимит.
```
